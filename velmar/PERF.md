# Производительность VELMAR

## Как мерили

`node tools/bench.mjs` (нужен запущенный `npm run dev`) открывает игру в headless Chromium для трёх пресетов
и четырёх сценариев:

- `street_day` — пешком на улице делового центра, 14:00;
- `night_rain` — та же улица ночью в грозу (мокрый асфальт, дождь);
- `aerial` — общий план города с высоты 260 м;
- `driving` — за рулём седана на закате, разгон.

Для каждого сценария сначала идёт прогрев (стриминг чанков, спавн трафика и пешеходов), затем 60 шагов симуляции
без рендера (это «CPU симуляции») и серия кадров с рендером. Снимаются `renderer.info`: draw calls и треугольники
за кадр, включая все проходы (каскады теней, GTAO, bloom).

> **Важно.** В облачной среде нет GPU: Chromium рисует через SwiftShader (программный растеризатор на CPU).
> Поэтому миллисекунды кадра в headless (0,4–4 с) **не отражают** скорость телефона и в таблицу не включены.
> Draw calls, треугольники и CPU-время симуляции от видеокарты не зависят. Их и нужно сравнивать.

## Что сделано для мобильных

| Приём | Где |
|---|---|
| Стриминг чанков 200×200 м: детальная геометрия (LOD0) строится по мере приближения, не больше 1 чанка за кадр, и выгружается с гистерезисом | `world/World.ts` |
| LOD: дальние кварталы — упрощённые «коробки» (LOD1, ~28 тыс. треугольников на весь город) | `world/ChunkBuilder.ts` |
| Слияние геометрии: все здания и пропсы чанка — **один** draw call на материал (фасады, листва, огни, неон) | `world/GeomBuilder.ts` |
| Окна, разметка, плитка, лужи — процедурно в шейдере, без текстур | `render/Materials.ts` |
| Инстансинг: колёса всех машин, лампы светофоров, частицы, дождь, следы пуль, пятна фар | `entities/VehicleManager.ts`, `render/*` |
| Персонаж — одна SkinnedMesh (18 костей, 1 draw call), дальние NPC (>95 м) не рендерятся и не анимируются | `entities/CharacterModel.ts`, `game/Game.ts` |
| Тени: CSM 1/2/3 каскада, в карты теней попадают только ближние чанки, машины и люди; деревья отбрасывают тень только на High | `render/SkySystem.ts`, `world/World.ts` |
| Трафик — кинематика по полосам (без физики), в Rapier переходит только при ДТП | `ai/Traffic.ts` |
| Пулы и лимиты: пешеходы, трафик, частицы, дождь, полиция — по пресету | `core/Quality.ts` |
| Карта окружения (PMREM) перестраивается раз в 2–8 с и только при сдвиге солнца | `render/SkySystem.ts` |
| GTAO в половинном разрешении и только на High | `render/PostFX.ts` |
| Динамическое разрешение: медиана времени кадра → масштаб 0,55–1,0 | `core/Quality.ts` (`FrameGovernor`) |
| Авто-пресет: при устойчивых < 24 FPS на минимальном масштабе пресет понижается, при > 58 FPS — повышается | `core/Quality.ts` |
| Упрощённая генерация на Low: без карнизов, деревьев вдоль улиц, половина лесов | `world/ChunkBuilder.ts` |

## Пресеты

| | Low | Medium | High |
|---|---|---|---|
| Макс. pixelRatio | 1.0 | 1.5 | 2.0 |
| Каскады теней / размер / дальность | 1 / 1024 / 70 м | 2 / 1024 / 140 м | 3 / 2048 / 300 м |
| Постобработка | нет | Bloom + ACES + FXAA | GTAO (½ разрешения) + Bloom + ACES + MSAA×4 |
| Детализация (LOD0) | 220 м | 300 м | 460 м |
| Дальность прорисовки | 850 м | 1300 м | 2200 м |
| Пешеходы / машины | 12 / 10 | 22 / 16 | 34 / 24 |
| Капли дождя | 1500 | 3500 | 7000 |

Пресет по умолчанию выбирается по устройству (`guessInitialQuality`): слабый телефон → Low,
остальные телефоны → Medium, десктоп с 8+ потоками → High. Дальше работает автоподстройка по FPS.

## Что не измерено

Реальный FPS на конкретных Android-телефонах здесь замерить нельзя: нет устройства и GPU.
Включите «Показывать FPS» в настройках (или добавьте `?stats` к адресу), там видны FPS, время кадра, draw calls,
треугольники, пресет и масштаб разрешения в реальном времени.
